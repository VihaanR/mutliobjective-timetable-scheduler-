6. Compare solvers

Runs the selected solvers back-to-back against the current data and compares them head-to-head. This is one synchronous request — it does not create a run in the history table below and has no export links; cpsat/pipeline can each take 20–60s, so comparing all three can take a few minutes.

Lower soft cost is better. Hard violations dominate: any result with hard violations above zero ranks below one with zero, regardless of soft cost.

7. Pareto trade-off sweep

Traces the actual trade-off frontier between competing objectives (faculty day-load balance, student idle-gap/day-span cost, late-lab-slot placement) using an epsilon-constraint sweep on the CP-SAT model — reveals trade-offs a single scalarized soft-cost number hides. Each pair does several CP-SAT solves, so this runs as a background job like Generate above; a full 3-pair sweep at the defaults can take several minutes.

8. Holiday / rain adjustment

Adjust the current timetable (run —) for a sudden holiday or rain. The blocked window is closed off and the whole week is re-solved around it, warm-started from the current timetable — so a rained-out session is rescheduled elsewhere in the week rather than dropped. Most unaffected sessions stay put, but that is a tendency, not a guarantee. The stored run is never changed.
